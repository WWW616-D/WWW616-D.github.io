这篇博客会记录一些我在阅读这一章节时一些自认为值得在意的点。

7.1：

  • 在考虑用函数模拟运算符重载时，将*this作为返回值可以达成链式调用的目的。
  • istream和ostream是两种类类型，平时使用cout和cin都是其中的类，它们实现的输入和输出操作只是运算符重载的结果。输入和输出操作会对它们造成一些状态上的改变
  • 使用列表法的构造函数可以避开类内部成员的初始化，以提高程序的效率。
  • ::运算符和我之前想的不太一样，不只是命名空间作用域的符号，还可以用来访问类中的特定类型，别名，静态变量，比如以下代码
  • const 和mutable是编译期的概念，不会在后续汇编代码中体现。

7.3

友元类是你声明后对方可以访问你的数据，这有一点点单向讨好的意思在(?)大概就是，你无权决定对方是否给你访问只能决定你自己给谁访问。

也可以只给某个类的成员函数访问权限，但这样操作的定义声明顺序狠严苛。如果要对对方类的一组重载函数提供友元声明，那么每一个都要给。

小贴士:友元声明不一定是真的声明

7.4

类在查找名字时表现的相当智能，会优先使用自己类内声明定义的内容，不分上下。

函数得到的参数可能会隐藏类成员内部的参数，这种时候可以考虑用this指针表达，但最好别出现这种情况。初始化列表就不会混淆它们

函数查名顺序:内部->所属类->外部作用域

7.5

如果类成员是const或者引用之类的，必须使用构造函数初始化列表进行赋值

类成员的初始化顺序与其在声明顺序一致
